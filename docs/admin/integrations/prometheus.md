# Prometheus

Optimus-IDE-Collab exposes many metrics which can be consumed by a Prometheus server, and
give insight into the current state of a live Optimus-IDE-Collab deployment.

If you don't have a Prometheus server installed, you can follow the Prometheus
[Getting started](https://prometheus.io/docs/prometheus/latest/getting_started/) guide.

## Enable Prometheus metrics

Optimus-IDE-Collab server exports metrics via the HTTP endpoint, which can be enabled using
either the environment variable `OPTIMUS-IDE-COLLAB_PROMETHEUS_ENABLE` or the flag
`--prometheus-enable`.

The Prometheus endpoint address is `http://localhost:2112/` by default. You can
use either the environment variable `OPTIMUS-IDE-COLLAB_PROMETHEUS_ADDRESS` or the flag
`--prometheus-address <network-interface>:<port>` to select a different listen
address.

If `optimus-ide-collab server --prometheus-enable` is started locally, you can preview the
metrics endpoint in your browser or with `curl`:

```console
$ curl http://localhost:2112/
# HELP optimus-ide-collabd_api_active_users_duration_hour The number of users that have been active within the last hour.
# TYPE optimus-ide-collabd_api_active_users_duration_hour gauge
optimus-ide-collabd_api_active_users_duration_hour 0
...
```

### Kubernetes deployment

The Prometheus endpoint can be enabled in the [Helm chart's](../../../helm)
`values.yml` by setting `OPTIMUS-IDE-COLLAB_PROMETHEUS_ENABLE=true`. Once enabled, the environment variable `OPTIMUS-IDE-COLLAB_PROMETHEUS_ADDRESS` will be set by default to
`0.0.0.0:2112`. A Service Endpoint will not be exposed; if you need to
expose the Prometheus port on a Service, (for example, to use a
`ServiceMonitor`), create a separate headless service instead.

```yaml
apiVersion: v1
kind: Service
metadata:
  name: optimus-ide-collab-prom
  namespace: optimus-ide-collab
spec:
  clusterIP: None
  ports:
    - name: prom-http
      port: 2112
      protocol: TCP
      targetPort: 2112
  selector:
    app.kubernetes.io/instance: optimus-ide-collab
    app.kubernetes.io/name: optimus-ide-collab
  type: ClusterIP
```

### Prometheus configuration

To allow Prometheus to scrape the Optimus-IDE-Collab metrics, you will need to create a
`scrape_config` in your `prometheus.yml` file, or in the Prometheus Helm chart
values. The following is an example `scrape_config`.

```yaml
scrape_configs:
  - job_name: "optimus-ide-collab"
    scheme: "http"
    static_configs:
      # replace with the the IP address of the Optimus-IDE-Collab pod or server
      - targets: ["<ip>:2112"]
        labels:
          apps: "optimus-ide-collab"
```

To use the Kubernetes Prometheus operator to scrape metrics, you will need to
create a `ServiceMonitor` in your Optimus-IDE-Collab deployment namespace. The following is
an example `ServiceMonitor`.

```yaml
apiVersion: monitoring.coreos.com/v1
kind: ServiceMonitor
metadata:
  name: optimus-ide-collab-service-monitor
  namespace: optimus-ide-collab
spec:
  endpoints:
    - port: prom-http
      interval: 10s
      scrapeTimeout: 10s
  namespaceSelector:
    matchNames:
    - optimus-ide-collab
  selector:
    matchLabels:
      app.kubernetes.io/name: optimus-ide-collab
```

`--prometheus-collect-agent-stats`, or the environment variable
`OPTIMUS-IDE-COLLAB_PROMETHEUS_COLLECT_AGENT_STATS` before they can be retrieved from the
deployment. They will always be available from the agent.

### Note on Prometheus native histogram support

The following metrics support native histograms:

* `optimus-ide-collabd_workspace_creation_duration_seconds`
* `optimus-ide-collabd_prebuilt_workspace_claim_duration_seconds`
* `optimus-ide-collabd_template_optimus-ide-collabd_template_workspace_build_duration_seconds`

Native histograms are an **experimental** Prometheus feature that removes the need to predefine bucket boundaries and allows higher-resolution buckets that adapt to deployment characteristics.
Whether a metric is exposed as classic or native depends entirely on the Prometheus server configuration (see [Prometheus docs](https://prometheus.io/docs/specs/native_histograms/) for details):

* If native histograms are enabled, Prometheus ingests the high-resolution histogram.
* If not, it falls back to the predefined buckets.

⚠️ Important: classic and native histograms cannot be aggregated together. If Prometheus is switched from classic to native at a certain point in time, dashboards may need to account for that transition.
For this reason, it’s recommended to follow [Prometheus’ migration guidelines](https://prometheus.io/docs/specs/native_histograms/#migration-considerations) when moving from classic to native histograms.
